# MemoKeel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename the widget to MemoKeel with automatic data migration, replace the left nav rail with a top tab bar, restyle header/footer, add keyboard shortcuts, and add Dashboard and Tags modes — without changing the shared theme.

**Architecture:** The rename touches identity strings, the icon file, and the data path; `store.sh` gains a one-shot legacy-directory migration driven by a new `QN_MIGRATE_FROM` env var that `main.qml` computes. `NavRail.qml` is replaced by `TabBar.qml` and `FullView.qml`'s shell is re-laid-out around it. Two new views (`DashboardView.qml`, `TagsView.qml`) are pure consumers of existing controller intents.

**Tech Stack:** QML (Qt 6.11 / Plasma 6), Kirigami, bash store broker.

## Global Constraints

- **The theme must not change.** `package/contents/ui/theme/QN.qml` and `package/contents/code/theme.js` are shared across all Conqrex widgets. No new colors, no palette edits. Every view reads surface/text colors from `T.QN` tokens (`import "theme" as T` from `ui/`, `import "../theme" as T` from `ui/components/`); `Kirigami.Theme.highlightColor` remains acceptable as a selection/focus accent, and the `code/theme.js` neon keys (`cyan sky violet lime amber rose slate`) stay exactly as they are.
- No change to `package/contents/code/schema.js`, `code/model.js`, or the on-disk document format. `store.sh` changes are limited to the migration path described in Task 1.
- All user-visible strings wrapped in `i18n()`; strings with values use `i18n("… %1", value)` placeholders, never concatenation.
- New package id: `com.conqrex.memokeel`. New data dir: `<GenericDataLocation>/conqrex/memokeel`. Legacy dir `<GenericDataLocation>/conqrex/quicknotes` is read-only during migration and never deleted.
- Shortcuts use Ctrl (Linux), displayed as `Ctrl+N` etc., never `⌘`.
- Qt6 qmllint is at `/usr/lib/qt6/bin/qmllint` — the one on PATH is a Qt5 build and will mislead you.
- No test framework exists. Verification per task = qmllint clean on touched files + `plasmoidviewer` load + headless probes for logic. Pointer input CANNOT be driven in this environment; never claim interactive verification.

- [ ] **Step 4: Add legacy migration to `store.sh`**

At the top of `store.sh`, change the default data dir and add the legacy source:

```sh
DATA_DIR="${QN_DATA_DIR:-${XDG_DATA_HOME:-$HOME/.local/share}/conqrex/memokeel}"
MIGRATE_FROM="${QN_MIGRATE_FROM:-}"
```

Add this function above the command dispatch, and call it from `cmd_load` before the store is first read (it must run inside the same `flock` discipline the rest of the file uses — follow the existing locking pattern in `cmd_save`/`cmd_load` rather than inventing a new one):

```sh
# One-shot import of a pre-rename data directory. Copies, never moves: the
# legacy directory is left untouched as the user's fallback. No-op unless the
# caller names a legacy dir that has a store.json and our own store.json is
# absent, so it cannot fire twice and cannot overwrite live data.
MIGRATED_FROM=""
maybe_migrate_legacy() {
    [ -n "$MIGRATE_FROM" ]            || return 0
    [ "$MIGRATE_FROM" != "$DATA_DIR" ] || return 0
    [ -f "$MIGRATE_FROM/store.json" ] || return 0
    [ ! -f "$STORE" ]                 || return 0

    mkdir -p "$DATA_DIR" || return 0
    cp -a "$MIGRATE_FROM/store.json" "$STORE.migrating" 2>/dev/null || return 0
    for d in attachments backups journal; do
        [ -d "$MIGRATE_FROM/$d" ] && cp -a "$MIGRATE_FROM/$d/." "$DATA_DIR/$d/" 2>/dev/null
    done
    mv -f "$STORE.migrating" "$STORE" || return 0
    MIGRATED_FROM="$MIGRATE_FROM"
    err "store.sh: migrated data from $MIGRATE_FROM"
}
```

`store.json` is copied to a `.migrating` temp and renamed last, so an interrupted migration cannot leave a half-written store behind. Attachment/backup/journal copies are best-effort: a failure there must not abort the migration or lose the document.

Then include the marker in the document `cmd_load` prints, adding `"migratedFrom": "<path>"` only when `MIGRATED_FROM` is non-empty. Match how the file already injects top-level fields; do NOT persist this field into `store.json` — it is transport-only, and `schema.js`/`model.js` must not learn about it.

Also update the header comment block: the widget name, and the data-dir line naming the new default plus the `QN_MIGRATE_FROM` behaviour.
